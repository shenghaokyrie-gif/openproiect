## 目录规范

```
openproiect/
├── README.md                  # 本文件：索引与规范
├── _template/                 # 新项目骨架，不参与编号
│   └── README.md
├── 01-water-ics-testbed/      # 01 = 项目编号
│   ├── README.md              # 项目入口：解决什么问题、方案边界、文件说明
│   ├── 实施方案.md             # 正文（中文文档用中文名）
│   ├── 部署手册.md             # 操作手册 / 验收检查表
│   ├── templates/             # 可直接复用的配置/代码模板
│   └── reference/             # 技术核对材料：参数口径、版本约束
└── 02-...                     # 下一个项目
```

四条约定：

1. **编号补零两位**（`01`、`02`…`10`）。不是为了好看——不补零的话 `10-` 会排在 `2-` 前面。
2. **目录名、代码文件名用 ASCII**（`01-water-ics-testbed`、`scenario-template.yaml`），
   **文档内容与文档文件名用中文**。这样跨平台/命令行不出编码问题，人读起来又不用猜。
3. **每个项目目录里必须有 `README.md`**，且必须回答三个问题：解决什么问题、方案边界在哪、里面每个文件干什么用。
4. **`reference/` 放技术核对材料**（参数口径、版本约束、模块职责），正文只写我自己的设计与判断。
   两者分开，是为了结论可核、责任可追。

## 状态取值

| 状态 | 含义 |
|---|---|
| 方案完成，待实跑 | 设计与文档完成，尚未上机验证 |
| 实验进行中 | 有部分实测数据 |
| 已验证 | 结论有可复现的实验支撑 |
