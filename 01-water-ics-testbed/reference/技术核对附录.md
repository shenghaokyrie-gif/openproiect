## 1. 项目定位

**一句话**：DHALSIM（Digital HydrAuLic SIMulator）是一个把 **EPANET 水力仿真**（经 WNTR / epynet）与 **Mininet + MiniCPS 工业控制网络仿真**耦合起来的**联合仿真测试床（co-simulation testbed）**，为供水管网 ICS/SCADA 的网络攻击实验同时产出**物理真值**与**真实网络报文**。

- 自我定位：面向供水管网的联合仿真测试床，多机构合作项目。
- 解决什么痛点（`README.md:4`）：单纯水力仿真没有网络流量，单纯网络靶场没有物理反馈。DHALSIM 在物理数据之外还能给出 `PLCs、SCADA server 以及其他网络/工业设备` 的**网络抓包**，让"攻击 → 报文 → 控制器行为 → 水力后果"这条链可以被同一实验度量。
- 归属判断：**数字孪生测试床 / 研究基础设施**，**不是可部署产品**。证据：
  - 入口是 `sudo dhalsim <config.yaml>`，需要 root、Mininet、内核 netfilter（`README.md:26`、`doc/installation.rst`）；
  - 无 REST/gRPC/服务化接口，无安装包发布，版本号停在 1.1.1；
  - 示例拓扑以"教学/复现实验"口吻维护，且 WADI 例子被显式标记为 unsupported（见 §7）。
- 与常见描述的**出入**（重要）：
  - 它**不是**微服务/消息中间件架构（**没有** Kafka / MQTT / REST / ZeroMQ）。进程间同步靠**单个 SQLite 文件**；工业协议层是 **ENIP/CIP over TCP**。
  - 它里面的"SCADA"**不是**真实 SCADA 产品（不是 OpenSCADA/IGNITION），而是 MiniCPS 风格的自研 Python 轮询器（`dhalsim/python2/generic_scada.py`），也没有 historian。
  - "数字孪生"指的是**与 EPANET 模型同步**，不是与真实水厂在线同步。

### 4.4 `install.sh` 额外装的东西（决定它为什么只能跑在 Ubuntu 上）

1. `apt install git python3 python3-pip curl`；`pip install cppo`
2. clone **MiniCPS**（`afmurillo/minicps`）并 `pip install .`
3. clone **DHALSIM-epynet**（`afmurillo/DIHALSIM-epynet`，即 epynet 分支）并 `pip install .`
4. **从源码编译 Mininet `2.3.1b4`**（`PYTHON=python3 ./util/install.sh -fnv`）
5. `apt install libnfnetlink-dev libnetfilter-queue-dev` + `pip install -U git+https://github.com/kti/python-netfilterqueue`（**MITM/DoS 依赖内核 NFQUEUE**）
6. `pip install -e .`（可选 `-t` 测试依赖 / `-d` 文档依赖）

`pyproject.toml` 只声明 build backend（`setuptools==59.8.0` + `wheel`），无 PEP 621 metadata。

### 4.5 与 WNTR / EPANET 的关系（明确回答）

- **DHALSIM 是 EPANET 的上层编排者，不是替代品，也不是 EPANET 的 fork。**
- 它对 EPANET 有**两条互斥的 Python 绑定**，用配置项 `simulator:` 选择（`doc/configuration.rst`）：
  - `wntr`：US EPA 官方的 EPANET Python 封装（"Python wrapper developed by U.S. Environmental Protection Agency, the same team that developed EPANET"）。
  - `epynet`：epynet 的定制分支（`afmurillo/DHALSIM-epynet`）；逐步仿真实现更好，性能高于 WNTR。
  - `doc/configuration.rst` 写默认值是 `wntr`，但**所有 5 个示例拓扑都用 `simulator: epynet`**（`examples/anytown_topology/anytown_config.yaml`、`ctown_config.yaml` 等）。
- 代码里的分支点非常明确：`dhalsim/physical_process.py:80-89`（`if self.simulator == 'epynet' ... elif 'wntr' ... else 警告并回落 epynet`）。
- 关键差异（不是文档宣传，是代码事实）：
  - 走 `epynet` 时，DHALSIM 会**先把 `.inp` 里的 `[CONTROLS]` 段删掉**，另存为 `*_processed.inp`，控制逻辑改由 PLC 进程实施（`physical_process.py:211-239`，`remove_controls_from_inp_file()`）。
  - `wntr` 后端下"pump speed"不被支持，会抛 `InvalidControlValue`（`dhalsim/python2/generic_plc.py` 的 `set_tag()`）；`epynet` 后端下能直接设泵速。
  - `wntr` 后端对初始化 junction 压力有妥协：代码里初始值直接写 `0`（`physical_process.py` 的 `register_initial_results()`，含 `# toDo: Check in wntr 0.4.2 a new way of getting the initial junction pressure`）。
- `demand` 选项 `PDD`/`DD` 直接透传给 WNTR 的 hydraulic demand model（`doc/configuration.rst`）；`epynet` 路径下同样设置 `wn.options.hydraulic.demand_model = 'PDD'`（`physical_process.py` `prepare_wntr_simulator()`）。

### 5.2 场景（scenario）如何定义与加载

**一个实验最少 3 个文件**（`doc/user_guide.rst`）：
1. **`.inp`** — EPANET 管网文件（拓扑、管径、需水量、`[CONTROLS]`）；
2. **主 YAML config** — 实验参数；
3. **PLCs YAML** — 声明几台 PLC、各自负责哪些 sensor/actuator。

主配置可用 `!include` 任意拆分（`pyyaml-include`）。最小实例（`examples/anytown_topology/anytown_config.yaml`，原文）：

```yaml
inp_file: anytown_map.inp
output_path: output
iterations: 2880
network_topology_type: complex
plcs: !include anytown_plcs.yaml

simulator: epynet
demand: pdd
log_level: debug
demand_patterns: demands_anytown_small.csv
#attacks: !include anytown_concealment_mitm.yaml
#attacks: !include anytown_dos.yaml
```

PLCs 文件（`examples/anytown_topology/anytown_plcs.yaml`，原文）——注意它可以直接引用 `.inp` 里的对象名：

```yaml
- name: PLC1
  actuators:
    - P78
    - P79
- name: PLC2
  sensors:
    - T41
- name: PLC3
  sensors:
    - T42
```

加载链路：`Runner` → `ConfigParser(config_file)` → `generate_intermediate_yaml()` → **`intermediate.yaml`**（这是真正被所有子进程读取的"物化场景"）→ `DatabaseInitializer(intermediate).write()` → `automatic_run.py` 读同一个 intermediate。

`intermediate.yaml` 里被实际消费的顶层键（由 `physical_process.py` 的代码取值穷举得到，行号见 `_pp` 引用）：
`config_path`、`inp_file`、`output_path`、`db_path`、`simulator`、`demand`、`log_level`、`iterations`、`plcs`、`network_attacks`、`saving_interval`、`batch_index`、`batch_simulations`、`initial_tank_values`、`demand_patterns_data`、`start_time`。

每台 PLC/SCADA 在 intermediate 里会被补全网络编址字段。实测样例（`test/auxilary_testing_files/intermediate_yaml_network_attacks.yaml`）中，一条 PLC 条目的键为：
`name, sensors, actuators, controls, interface, local_ip, mac, public_ip, gateway_name, gateway_ip, gateway_inbound_mac, gateway_outbound_mac, provider_interface, provider_ip, provider_mac, switch_name`。
→ 即 **DHALSIM 自动分配内网/公网地址与网关 MAC，供 ARP 欺骗使用**（`Network` 层细节）。

拓扑类型二选一（`doc/configuration.rst`）：
- `simple`：所有 PLC + SCADA 在同一局域网，PLC 接一个 switch，SCADA 接另一个 switch，共用一个 router；
- `complex`：每台 PLC / SCADA 各有独立 switch+router，经公网 IP 连到中心 router；"This makes testing of attacks such as man in the middle more realistic"。

### 5.3 传感器 / 执行器模型

**传感器类型（只有 4 类，`doc/configuration.rst`）**：
| 类型 | 写法（用 `.inp` 里的名字） |
|---|---|
| Tank level | 水箱名，如 `T41` |
| Junction pressure | 节点名，如 `Junction5` |
| Valve flow | 阀名 + `F`，如 `V3F` |
| Pump flow | 泵名 + `F`，如 `P2F` |

- **水质（chlorine/quality）传感器：未查到**（代码与文档均只出现 level/pressure/flow）。
- **噪声**：配置项 `noise_scale`，"the scale of the **Gaussian noise** added to the sensor values that are sent by the PLCs"，默认 `0`（无噪声）。示例里 `wadi_config.yaml` 用 `noise_scale: 0.25`。（`doc/configuration.rst`、`examples/wadi_topology/wadi_config.yaml`）
- **采样频率**：没有独立的"采样率"参数。采样与仿真迭代**同频**：每个 hydraulic timestep 一轮，PLC 把本地 system state 通过 ENIP 送出、SCADA 轮询取走。PLC 侧的缓存刷新线程周期是硬编码常量 `PLC_CACHE_UPDATE_TIME = 0.05`（秒）（`dhalsim/python2/generic_plc.py`）。
- 物理量来源口径差异（关键）：走 `epynet` 时 **tank 取 `tanklevel`**，走 `wntr` 时 **tank 取 `node.level`**，而 junction 在 `wntr` 下用 `head - elevation` 折算压力、在 `epynet` 下直接读 `pressure`（`physical_process.py:806-878` 的 `update_tanks/update_junctions`）。

**执行器类型（只有 2 类，`doc/configuration.rst`）**：
| 类型 | 说明 |
|---|---|
| Valve status | 用阀名，取值 open / closed |
| Pump status | 用泵名，取值 open / closed；**泵速（speed）仅 epynet 支持** |

DHALSIM 会把 `.inp` 的 `[CONTROLS]` 解析成 PLC 侧规则（`entities/control.py` 的 `AboveControl`/`BelowControl`/`TimeControl`），因此"就地控制"是在 PLC 里执行的，不是在 EPANET 里执行（epynet 路径下 `.inp` 的 controls 已被剥离）。

### 5.4 攻击模型（attack injection）

分两大类，配置块名不同（`doc/configuration.rst` 示例、`init_database.py` 建表逻辑、`physical_process.py:562` 的 `get_attack_flag()`）。

**(a) `device_attacks`（设备侧 / 直接改执行器）**
写法（`examples/wadi_topology/wadi_attacks.yaml`，原文）：
```yaml
device_attacks:
  - name: V_ER2i_attack
    trigger:
      type: time
      start: 125
      end: 375
    actuator: V_ER2i
    command: closed
```
触发类型 4 种（`dhalsim/python2/entities/attack.py` 的类）：`time`（start/end 迭代号）、`below`（sensor+value）、`above`（sensor+value）、`between`（sensor+lower_value+upper_value）。实现上 `apply(plc)` 每轮读 `plc.get_master_clock()`，命中条件则 `plc.set_attack_flag(True, name)` 并 `plc.set_tag(actuator, command)`——**攻击是通过 PLC 自身的 set_tag 落地的，等于篡改控制器输出**。

**(b) `network_attacks`（网络侧 / 中间人、DoS、隐蔽）**
`type` 取值（文档 + 示例 + 模块名交叉验证）：`mitm`、`naive_mitm`、`simple_dos`、`concealment_mitm`（另有未在示例中出现的 `replay_mitm`、`black_box_concealment`、`unconstrained_blackbox` 等实现文件）。

`mitm`（`examples/anytown_topology/anytown_mitm.yaml`，原文）：
```yaml
network_attacks:
  - name: plc1attack
    type: mitm
    target: PLC1
    offset: 7.0
    trigger:
      type: time
      start: 5
      end: 20
```
`simple_dos`（`examples/anytown_topology/anytown_dos.yaml`，原文）：
```yaml
network_attacks:
    - name: plc1attack
      target: PLC1
      trigger:
        type: time
        start: 648
        end: 792
      type: simple_dos
      direction: destination
```
`concealment_mitm`（`examples/ctown_topology/ctown_concealment_mitm_value.yaml`）：在 MITM 基础上加 `concealment_data:`，`type: value` + `concealment_value: [{tag: T3, value: 42.0}, {tag: T4, value: 84.0}]`，即**把被篡改的量在 SCADA 视角"伪装"成合理值**；另有 `type: <路径型>` 变体（`ctown_concealment_mitm_path.yaml`）与基于 Keras 生成模型的变体（`network_attacks/black_box_concealment_attack.py` + `adversarial_models/`）。

统一的攻击字段（`test/auxilary_testing_files/intermediate_yaml_network_attacks.yaml` 实测）：`name, type, target, trigger{type,start,end | sensor,value | lower_value,upper_value}, tags[{tag, value | offset}], offset, value, direction`。

**攻击实现的技术栈**（这是"能力"的实质）：
- `dhalsim/network_attacks/utilities.py`：`get_mac()`（ARP 请求）、`launch_arp_poison(ip1, ip2)`、`spoof_arp_cache()`、`restore_arp()` —— **用 Scapy 做双向 ARP 欺骗**把流量牵到攻击者；
- `translate_payload_to_float(raw)` / `translate_float_to_payload(float, raw)`：**直接改报文最后 4 字节**（`struct.unpack('<f', raw_payload[-4:])`），即针对 CIP 里 32-bit REAL 的定点篡改；
- `dhalsim/network_attacks/enip_cip_parser/{enip_tcp,cip,utils}.py`（合计约 34 KB）：自研 ENIP/CIP 协议解析，用于找到要改的 tag 字段；
- `*_netfilter_queue.py` 系列（如 `concealment_netfilter_queue.py` 16 KB、`unconstrained_blackbox_netfilter_queue.py` 18 KB）：用 Linux **NFQUEUE** 在用户态拦截/改写转发报文；
- `cppo_server_mitm_attack.py`：与 `cppo`（ENIP 服务端库）联动。

**(c) `network_events`（非攻击的网络扰动，仅影响链路）**
`doc/events.rst` 原话："Events are situations started by a trigger that do not necessarily are attacks… do not require launching additional mininet nodes"。**目前只支持 `packet_loss`**，用 Linux `tc` 实现，`value` 是丢包百分比：
```yaml
network_events:
  - name: link_loss
    type: packet_loss
    target: PLC1
    trigger:
      type: time
      start: 648
      end: 792
    value: 25
```
（`doc/events.rst`、`doc/configuration.rst`）→ 另有 `network_delay`（`network_events/network_delay.py`）与 `delay_and_loss` 实现文件，但**文档只承诺 `packet_loss`**。

### 5.5 与外部系统的对接方式（明确回答：**都不用**）

**没有 Kafka / MQTT / REST / ZeroMQ。** 实际接口有四层：

1. **工业协议层**：**ENIP/CIP over TCP**。PLC 侧是 `cppo` 实现的 EtherNet/IP 服务端（`plc_protocol = {'name': 'enip', 'mode': 1, 'server': plc_server}`，见 `generic_plc.py`），SCADA 侧是客户端轮询。MAC/IP 由拓扑自动分配。
2. **网络层**：**Mininet**（`TCLink`）+ Open vSwitch + `tc`；`simple`/`complex` 两种拓扑；每台 PLC/SCADA 一个 gateway/router。
3. **进程间同步层**：**单个 SQLite 文件**（`db_path`），是本项目最反直觉的设计选择。表与用途（由 `physical_process.py` 的 SQL 直接确认）：
   - `plant(name, pid, value)` — 所有物理量/执行器状态的**共享内存**，主键 `(name, pid)`（预处理语句 `UPDATE plant SET value = ? WHERE name = ?`，`physical_process.py:122`）；
   - `master_time(id, time)` — 全局逻辑时钟，单行 `id=1`（`REPLACE INTO master_time (id, time) VALUES(1, ?)`，`:738`）；
   - `sync(name, flag)` — 每个 PLC + `scada` + 每个攻击者各一行，flag 状态机（`:139`、`:554-560`）；
   - `attack(name, flag)` — 攻击是否处于激活态（`:562-568`）；
   - `event(name, flag)` — 网络事件激活态（`init_database.py`）。
   高并发下用 `DB_TRIES=10` 次重试 + `random.uniform(0.01, 0.1)` 秒随机退避来绕开 SQLite 的写锁（`physical_process.py:44`、`:124`、`:141-176`）。
4. **产物层**：`.pcap`（每台 PLC / 每个攻击者 / SCADA 各一份，`plc_name.pcap`、`scada.pcap`）+ 两个 CSV：
   - `ground_truth.csv` — EPANET 里的**真实**物理量（含 attack 列）；
   - `scada_values.csv` — SCADA **在网络上看到**的值。
   "两者的差就是攻击效果"是这套设计的核心可观测性（`doc/running.rst`）。

**SCADA 数据回放（离线回灌）怎么做？→ 未查到。** 仓库里没有把历史 SCADA 数据回放进仿真的入口。名字相近的 `network_attacks/replay_mitm.py` 是**攻击侧的报文重放攻击**（截获后重发旧报文），与"SCADA 数据回放"不是一回事，不要混淆。

### 5.6 仿真时钟与实时性

- **时钟是"迭代计数"`master_time`**，不是墙钟。1 iteration = 1 个 hydraulic timestep（`doc/configuration.rst`: "One iteration represents one hydraulic time-step"）。
- **软同步状态机**（`physical_process.py:673-739`，`simulate_with_epynet()`）：

```
while internal_epynet_step:
    while not get_plcs_ready(1): sleep(0.005)   # 等所有 PLC 更新完本地缓存/CPPPO
    set_sync(2)                                  # 放行：PLC 可以开始收远端值
    while not get_plcs_ready(3): sleep(0.005)   # 等 PLC 应用控制逻辑
    update_actuators()                           # 从 DB 读回执行器状态
    internal_epynet_step, step_results = wn.simulate_step(simulation_time, actuator_list)
    update_tanks/pumps/valves/junctions(...)     # 物理量写回 DB
    register_results(...)                        # 攒 ground_truth 行
    set_sync(0)                                  # 交还控制权给 PLC
    REPLACE INTO master_time ...
```
- **实时性**：既**不保证实时**，也**不做固定倍速**。同步靠 5 ms 轮询 sleep，实际速度取决于 Mininet 里 ENIP 往返 + SQLite 争用；可以比真实时间快，也可以在复杂拓扑下变慢。**没有 RTOS / 时间同步（PTP）/ 硬实时调度**痕迹。
- **epynet 会跳步**：`simulate_step` 内部可能推进多个子步，DHALSIM 只把跨越 `hydraulic_step` 的那些步计入 `master_time`（`physical_process.py:702-717`），中间子步不记录。
- **事件驱动？** 没有离散事件调度器。所谓"事件/攻击触发"是**每个迭代轮询条件**判断（`TimeAttack.apply()` 比较 `start <= curr_time <= end`）。所以严格意义上是**时间步驱动的保守同步（conservative synchronization）联合仿真**。

## 7. 已知限制（区分「明确写明」与「从代码看出」）

**明确写明的**
1. **OS 锁定**：`README.md` 说 "install DHALSIM on an **Ubuntu 20.04** machine"；`doc/installation.rst` 说 "developed and tested on **Ubuntu 22.04** LTS… The installation script has not been tested on other versions"。**两处不一致**（20.04 vs 22.04）——这是仓库自身的文档矛盾，`install.sh` 里还写着 `version=$(lsb_release -rs)` 但实际未用于分支判断。
2. **WADI 拓扑已被放弃**：`examples/wadi_topology/readme.md` 原文 —— "The WADI topology presented here is **currently unsupported**, as DHALSIM version v0.6.0. We have left it in the repository for **educational purposes**"。但 `wadi_config.yaml` 仍会被 `doc/user_guide.rst` 当作可用示例列举 → 文档间矛盾，实际以 readme 为准。
3. **网络事件只支持一种**：`doc/events.rst` —— "Currently, **only `packet_loss` is supported**"。
4. **事件 vs 攻击的区别是配置层面的**：事件不需要额外 Mininet 节点（`doc/events.rst`）。
5. **同一节点叠加两个网络攻击"行为未测"**：`doc/user_guide.rst` —— "Multiple attacks can be executed at the same time. Nevertheless, **targeting the same node with two different network attacks might have untested behaviour**"。
6. **`scada_values.csv` 只含 PLC 文件里声明过的变量**：`doc/user_guide.rst` —— "the SCADA values file will only contain the variables present in the PLCs YAML file"。

**从代码/依赖结构看出的（重、要外部服务）**
7. **必须 root + 内核级依赖**：Mininet、Open vSwitch、`libnetfilter-queue-dev`、`tc`。在容器/CI 里跑要用 `--privileged`。
8. **依赖很重且锁死**：`tensorflow==2.13.1` + `keras==2.13.1` + `numpy==1.24.3` 是**必装**（写在 `install_requires` 而非 extras），但只被 concealment 类攻击用到；`python_requires>=3.8.10` 且 TF 2.13 只支持到 py3.11 左右 → 环境窗口窄。
9. **从源码编译 Mininet 2.3.1b4 + 三个 Git fork**（`afmurillo/minicps`、`afmurillo/DHALSIM-epynet`、`kti/python-netfilterqueue`）→ 无版本锁，上游一旦变动安装即失败。
10. **SQLite 充当进程总线**：所有进程争一个 writer 锁，靠 10 次重试 + 10–100 ms 随机 sleep 硬扛。拓扑一大（ctown/ky15、2880 迭代）性能与稳定性风险高，代码里到处是 `#time.sleep(0.3)` 之类的实验性注释。
11. **`python2/` 目录名与 Python 3 运行**：极易误导读者以为需要有 Python 2；实际 `command_line.py` 明确用 `python3` 拉起。
12. **走 epynet 时会改写你的 `.inp`**：生成 `*_processed.inp`（删掉 `[CONTROLS]`），意味着**原始 EPANET 控制规则不再生效**，控制全部由 PLC 承担；这会让"EPANET 原生控制"与"DHALSIM PLC 控制"两种实验口径难以对比。
13. **WNTR 后端功能残缺**：pump speed 不支持（`InvalidControlValue`）、初始 junction 压力写 0（代码里自带 `# toDo`）。
14. **仓库体积**：`dhalsim/network_attacks/training_data/ctown/training_data.csv` **79 MB**、`examples/ctown_topology/dataset/.../concealed_values.txt` **3.6 MB**、多个 100–260 KB 的 `.inp` → 全量 clone 成本高。
15. **无 package 发布**：未上 PyPI，只能 `pip install -e .`。
16. **`simple` 拓扑的 WNTR/EPANET 时间步未做性能隔离**：`simulate_with_wntr()` 里 `wn.options.time.duration = wn.options.time.hydraulic_timestep`（`physical_process.py:744`），即每次只模拟一个步长，靠外层循环推进；这是"能跑但慢"的设计。
