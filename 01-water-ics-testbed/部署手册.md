# 测试台部署手册

> 本手册用于在一台干净的 Ubuntu 上把测试台跑起来，并逐项验收它「配得上」做安全实验。
> 内容来自源码与文档核对，**尚未在目标机上实跑**（编写环境为 Windows，缺 Mininet / root / netfilter）。
> 用法：从 §0 顺次往下，每步打勾；跳过任何一步都会让后续结论不可信。

---

## 0. 先做决定：值不值得装

装它之前先确认三件事，任何一件不成立就别装：

- [ ] 我有一台**能 root 的 Ubuntu**（20.04 或 22.04，先试 22.04，失败再降 20.04）
- [ ] 我能接受**从源码编译 Mininet 2.3.1b4** 和三个无版本锁的 Git fork
- [ ] 我要的是**攻击样例 / 标注数据 / 安全实验**，不是数字孪生运行时

如果我只是想要水力计算 → 直接用 `WNTR` 或 `epanet-js`，别碰 DHALSIM。

## 1. 环境准备

```bash
# 建议开一台一次性虚拟机或 --privileged 容器，别装在长期使用的机器上
lsb_release -rs          # 确认 20.04 / 22.04
python3 --version        # 必须 >= 3.8.10，且建议 <= 3.11（TF 2.13 的限制）
```

```bash
git clone https://github.com/Critical-Infrastructure-Systems-Lab/DHALSIM.git
cd DHALSIM
git checkout <tag>       # 版本停在 1.1.1，先 checkout 固定版本，别用 master 漂着
chmod +x install.sh
./install.sh
```

**install.sh 会做的事**（心里有数，出问题时知道查哪）：

| 装的组件 | 用途 | 失败时的表现 |
|---|---|---|
| `cppo` | ENIP（EtherNet/IP）服务端库 | PLC 起不来 |
| `afmurillo/minicps` | MiniCPS 基类 | `BasePLC` import 失败 |
| `afmurillo/DHALSIM-epynet` | epynet 绑定（已改过的 fork） | `simulator: epynet` 直接崩 |
| Mininet **2.3.1b4**（源码编译） | 网络仿真 | `mn -c` 找不到 |
| `libnetfilter-queue-dev` + `kti/python-netfilterqueue` | NFQUEUE 报文改写 | 隐蔽类攻击失效 |
| `tensorflow==2.13.1` + `keras==2.13.1` | 只服务 concealment 攻击，但**必装** | 装不上就卡在这，最耗时 |

> 坑：`requirements.txt` 只有 3 行（pyyaml/mininet/scapy），**不要用它装环境**。

- [ ] `sudo mn --test pingall` 能跑通
- [ ] `python3 -c "import wntr, epynet, scapy, netfilterqueue"` 无报错
- [ ] `dhalsim --help` 有输出

## 2. 第一次运行（用自带 anytown 示例）

```bash
sudo dhalsim examples/anytown_topology/anytown_config.yaml
# 自定义输出目录：
sudo dhalsim examples/anytown_topology/anytown_config.yaml -o /tmp/run1
```

- [ ] 跑完不挂
- [ ] `output/` 下有 `ground_truth.csv`、`scada_values.csv`、`*.pcap`

**第一次跑就要核对的两件事**（很容易静默出错）：

1. 打开 `scada_values.csv` 看列名 ——它**只含 PLCs YAML 里声明过的测点**，
   我在 YAML 里写漏一个，它不会报错，只是没这一列。
2. 对比 `ground_truth.csv`（真实物理量）和 `scada_values.csv`（SCADA 看到的）——
   **没有攻击时两者应当一致或仅差噪声**。如果不一致，说明同步或读取口径有问题，
   后面所有攻击实验都不可信。

## 3. 写我自己的场景

三个文件，缺一个都不行：

```
my_network.inp        # EPANET 管网
my_config.yaml        # 实验参数
my_plcs.yaml          # PLC 与测点/执行器的绑定
```

启动顺序建议：**先跑无攻击基线，再加攻击**。基线跑不通，攻击结果没意义。

## 4. 逐项验收表（照着打勾）

| # | 检查项 | 为什么 | 怎么验 |
|---|---|---|---|
| 1 | `simulator` 用 `epynet` 还是 `wntr` | 示例全用 epynet；wntr 缺泵速、初始压力写 0 | 看 `output/*_processed.inp` 是否被生成 |
| 2 | 走 epynet 后 `.inp` 的 `[CONTROLS]` 会被删掉 | 原始 EPANET 控制规则失效，控制改由 PLC 承担 | 对比原始 `.inp` 与 `*_processed.inp` 的 `[CONTROLS]` 段 |
| 3 | PLCs YAML 里的测点名必须真实存在于 `.inp` | 不存在不会报错，只是没数据 | `grep` `.inp` 里的 `[JUNCTIONS]`/`[TANKS]`/`[PUMPS]`/`[VALVES]` |
| 4 | 执行器只用 valve/pump 的 open/closed | 泵速只有 epynet 支持 | — |
| 5 | `noise_scale` 默认 0 | 想要真实点噪声必须显式设 | 设 0.25 看 `scada_values.csv` 抖动 |
| 6 | 采样率不可配 | 与迭代同频，PLC 缓存刷新硬编码 0.05s | 别指望能模拟"传感器 1 分钟一采" |
| 7 | `network_events` 只用 `packet_loss` | 文档只承诺这一种 | 引用 `network_delay` 属超出承诺范围 |
| 8 | 同一节点别叠两个网络攻击 | 文档明说"行为未测" | 拆成两轮实验 |
| 9 | 时间单位是**迭代号**不是秒 | 触发条件 `start/end` 都按 iteration | 1 iteration = 1 hydraulic timestep |
| 10 | `master_time` 会跳过 epynet 内部子步 | 时序对齐会错位 | 首轮就导出 `master_time` 对照 |

## 5. 我给自己定的实验纪律

- **一次只改一个变量**。DHALSIM 的同步是保守的、参数又多，同时改两处就分不清因果。
- **每轮实验留 `intermediate.yaml`**。它是物化场景，是唯一能复现的凭据
  （`file_generator.py` 的 `InputFilesCopier` 会把输入文件拷进 output，别删 output）。
- **`*_processed.inp` 一定要留档**。因为它和原始 `.inp` 不同，
  不留档就没法解释结果为什么和 EPANET 原生跑出来的不一样。
- **大拓扑先小跑**。ctown / ky15 是 2880 迭代，SQLite 争用在那个量级才暴露。
  先用 minitown 跑通，再放量。

## 6. 已知会让我踩坑的地方（速查）

| 症状 | 原因 |
|---|---|
| `InvalidControlValue` | 用了 `wntr` 后端还想设泵速 |
| PLC 起来了但 SCADA 没数据 | PLCs YAML 里没声明该测点 |
| 结果和 EPANET 原生跑的对不上 | epynet 路径删了 `[CONTROLS]` |
| 隐蔽攻击没生效 | `netfilterqueue` / `libnetfilter-queue-dev` 没装好 |
| 装环境卡在 tensorflow | 必装但只服务 concealment，环境窗口窄（py<=3.11） |
| 越跑越慢 / 卡死 | SQLite writer 锁争用，拓扑太大 |
| WADI 示例跑不通 | v0.6.0 起已不支持，仅留作教学 |
| 找不到 `python2` 目录意义 | 目录名遗留，里面就是 Python 3 |
